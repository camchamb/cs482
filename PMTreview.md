# Product Review Notes

## GitHub Projects

core workflow:
- Has a board with different columns. Tasks will move from one column to another when done automatically. Can create new items linked with issues.  

how projects and stories/tasks are represented;
- Each project is a tab at the top. Tasks are boxes with a title and description within the columns. 

sprint, board, or status workflow;

- It doesn't have a dedicated sprint functionality. You can create different boards for sprints
It moves tasks from columns to show status workflow. 

reporting or progress-tracking features;

- It has subissues that can be a more granular progress-tracking. 

how blockers, decisions, notes, or risks appear;

- All information on blockers decisions and notes can be found in the issue itself by clicking on it. 

what seems useful for CS 482;

- Showing what items need to be worked on.
- Showing what status a certain item is on. 

what seems unnecessary for the course MVP.

- It doesn't have to connect to GitHub to automatically move tasks to different statues. 
- Insights and data. 


## Jira

core workflow;

- Create tasks in a board. These task can be dragged and moved from one status to another. At the end of a sprint all
uncompleted tasks can be moved to the next sprint. 

how projects and stories/tasks are represented;

- The board shows the current project being worked on. 
- The status are columns that have a button to add a task
- Tasks are a box with a title, due date, assignee, and sprint information. 

sprint, board, or status workflow;

- Each task is assigned to a sprint that has a due date. Uncompleted tasks can be moved to the next sprint.
- There is information and stats on the sprint. 

reporting or progress-tracking features;

- Has who is assigned to a task. 
- Drag to different statuses. 

how blockers, decisions, notes, or risks appear;

- They appear as icons or drop down menus in the board view. 
- Clicking on a task shows more information and can be edited. 

what seems useful for CS 482;

- Tracking who is working on a task. 
- Tracking what stage a task is at. 
- Ability to save notes and decisions. 

what seems unnecessary for the course MVP.

- Connected it with GitHub automatically.
- There's lots of summary statistics and metrics. 
- There's a recent activity showing all changes. 
- Different views of tasks. 

# MVP scope

In scope:

- Sprint board
- Tasks or ToDos
  - Notes and Description of Tasks
- Status of Tasks
- Data persistence
- Closing Sprints

Explicitly out of scope:

- Connection to GitHub. 
- Stats
- Record of all activity
- Different views of tasks. 

Deferred or optional ideas

- Multiple projects on the same account. 
- Sharing data between people
- AI sprint reports
